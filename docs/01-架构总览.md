# 01 · 架构总览

## 一、为什么需要这套系统

LLM 本质是**无状态的**——每一轮对话都是"重新投胎"。这让 AI  agent 有三个死穴：

| 症状 | 根因 |
|---|---|
| 每轮重新摸索环境 | 没有会话历史 |
| "我明明记得"却搜不到 | 记忆库结构不清，只查了一个库 |
| 定时任务重启就掉 | 用 schtasks 而非常驻进程 |

本架构用**四个层**解决：

```
档案层（永不删）  →  节点层（持续提炼）  →  检索层（毫秒路由）  →  服务层（常驻自启）
```

## 二、四层详解

### 1. 档案层（Archive）—— 完整性

```
Chroma drawers（43,110 条）    原始记忆切片，带 source_file + line_start/end
SQLite memories（260 条）      记忆主体，带 vitality_score + access_count
diary.md / experience/         流水与轮次（AI 的"亲历"）
```

**铁律：永不删除。** 修剪是一次性工程，节点提取才是长期路。

### 2. 节点层（Nodes）—— 联想锚点

```
Chroma closets（2,428 个）     摘要节点：topic | entities | →drawer_ref
SQLite paths（235 条）         触发条件：domain + disclosure + priority
memory_gists / memory_tags     node_extractor 产出
```

**节点是指针，不是拷贝**——这保证"档案不删"与"节点轻量"可以同时成立。

### 3. 检索层（Retrieval）—— 毫秒路由

```
recall_router.py
  ① 19 个 wing 关键词打分 → 候选分类
  ② 分词 OR 检索（英文词≥3字符，中文2-6字）
  ③ 命中词数排序
  ④ 无命中则全局兜底
  ⑤ 写日志（为训练专属路由器积累标注）

三通道：
  recall_chroma  → Chroma 主库（同 wing/room 膨胀 = 联想）
  recall_palace  → SQLite（vitality 加权 + path 膨胀）
  recall         → 文本文件（MEMORY/日记/笔记）
```

### 4. 服务层（Service）—— 常驻自启

```
mem_service.py（8950）
  · HTTP 接口：/recall /health /stats /mine
  · 内存缓存 LRU-200（重复查询 0 开销）
  · 内部定时 mine（每 4 小时，替代定时任务）

autostart_all.py（开机联携启动）
  · HKCU Run 键拉起（无需管理员）
  · CREATE_NO_WINDOW 无窗口
  · 端口健康检查
```

## 三、数据流

### 写入流（自动沉淀）
```
AI 工作产出（结论文件）
  → auto_mine / mem_service 定时 mine
  → mempalace mine <dir>
  → Chroma drawers +（regex 层）closets
  → [可选] node_extractor 用 LLM 提炼更富的节点
```

### 读取流（联想激活）
```
AI："我需要关于 X 的记忆"
  → recall_router（wing 路由）
  → 三通道并行检索
  → 命中节点 → 沿 wing/room 膨胀 → 记忆链
  → 返回 + 记日志
```

### 学习流（持续变准）
```
每次检索记录 {need, wing, hit}
  → 积累 100+ 条
  → 训练 sklearn（TF-IDF + LR）或 LAYA
  → 替换规则路由 → 越用越准的"专属路由器"
```

## 四、为什么不用 LAYA 做检索（重要认知）

LAYA（Convai System 1 决策模型）实测：
- 是 **zero-shot 快速判定器**，**没有 fit/train API**
- 19 分类 zero-shot 只有 0.362（低于随机基线）
- 32-60ms/条，需 GPU

**正确用法**：规则路由先行（零依赖可解释），日志攒够后训练轻量分类器（sklearn <1ms，100 条数据就能训）。

## 六、移植清单（换成你的环境）

1. `src/config.py`：ROOT / CHROMA_DB / SQLITE_DB / 端口
2. `mempalace --palace <你的路径> init`
3. mine 你的高价值目录（结论/笔记/交付物）
4. 启动 `mem_service.py`
5. （可选）HKCU Run 开机自启
