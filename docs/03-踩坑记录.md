# 03 · 踩坑记录（10 条实证）

> 全部来自 2026-10-24~25 一晚实战，每条都有复现条件与解法。

## 1. 两个库只查一个 → 98% 记忆搜不到

**症状**：搜"V37 验证"返回的全是无关内容（similarity 0.43）。

**根因**：记忆宫殿有**两个库**：
- Chroma（332MB，mempalace 真正用的，45,552 条）
- SQLite（3.2MB，memories 260 + paths 235）

之前的 recall 只查 SQLite → 98% 记忆漏掉。

**解法**：三通道都要查（Chroma → SQLite → 文本文件）。

---

## 2. HNSW 索引 92% 缺失 → 向量检索被禁用

**症状**：`mempalace_search` 返回：
```
"vector_disabled": true,
"vector_disabled_reason": "HNSW index holds 1,002 elements but sqlite has 12,494 embeddings - 11,492 drawers (92%) are missing"
```

**解法**（顺序不能错）：
```bash
# 1. 先停 MCP（它占文件锁，否则 repair 报 "held open by another process"）
taskkill /F /IM mempalace-mcp.exe   # 或用 psutil 杀
# 2. 重建
mempalace --palace <path> repair --mode from-sqlite --archive-existing --yes
# 3. MCP 由宿主自动重启
```
**结果**：12,538 / 12,000（divergence 4.3% = 正常 flush lag）。

---

## 3. mempalace daemon 起不来（writer 冲突）

**症状**：
```
DaemonError: writable daemon startup refused: another writer owns local backend 'chroma'
```

**根因**：**MCP server 本身就是常驻的 writer**，再起 daemon 必然冲突。

**解法**：不要起 daemon。分工：
- MCP = 唯一 writer（mine/写）
- 自建服务 = 只读（SQLite WAL 支持多进程并行读）

---

## 4. sqlite3 URI 模式 `LIMIT ?` 占位符报错

**症状**：
```
sqlite3.ProgrammingError: Incorrect number of bindings supplied.
The current statement uses 1, and there are 2 supplied.
```

**根因**：`connect("file:...?mode=ro", uri=True)` 模式下 `LIMIT ?` 不被识别为占位符。

**解法**：改字面量 `LIMIT 5`（记得先 `int()` 防注入）。

---

## 5. 补丁里用未定义变量，被 except 吞掉

**症状**：函数返回空，查了半小时。

**根因**：补丁里用了 `NL` 变量但没定义 → `NameError` 被 `except Exception: pass` 吞掉。

**解法**：
1. 落盘后**必须** `py_compile.compile(f, doraise=True)`
2. 异常里至少 `log(str(e))`，不要裸 `pass`
3. 写独立测试脚本验证核心逻辑

---

## 6. bash heredoc 多层转义吃反斜杠

**症状**：补丁写进目标文件后，`"\n"` 变成真换行 → f-string 断裂。

**根因**：`bash heredoc → Python 字符串 → 目标文件` 三层转义，`\\n` 每层都被吃一层。

**解法**：**一律用 `chr(10)` / `chr(92)`**，不写任何反斜杠字面量。

---

## 7. Git Bash 的 `/tmp` = 系统 Temp（污染别人）

**症状**：WorkBuddy 更新报"检测到应用安装目录下存在用户项目目录"。

**根因**：Git Bash 的 `/tmp` 实际映射到 `C:\Users\<用户>\AppData\Local\Temp`——我把守护脚本写进 `/tmp`，**落进了 WorkBuddy 的更新暂存目录**。

**解法**：临时文件统一写项目内目录（如 `<root>/_tmp/`）。

---

## 8. schtasks ONLOGON 要管理员

**症状**：`schtasks /create /sc onlogon` 报"拒绝访问"。

**解法**：用 **HKCU Run 注册表键**（不需要管理员）：
```bash
reg add "HKCU\Software\Microsoft\Windows\CurrentVersion\Run" //v "MyService" //t REG_SZ //d "\"<pythonw路径>\" \"<脚本>\"" //f
```

---

## 9. 系统 Python 的 psutil 反复被 IDE 更新搞坏

**症状**：
```
ImportError: cannot import name '_pswindows' from partially initialized module 'psutil'
```
（一晚坏了 3 次）

**根因**：IDE 更新时重写 `site-packages`，pip 装到一半被打断。

**解法**：**用独立 venv**（如 `<project>/venv/Scripts/pythonw.exe`），不依赖 IDE 的 Python。

---

## 10. 无窗口启动：wscript 被安全策略拦

**症状**：命令被拦 `Known Windows LOLBin that can execute arbitrary code`。

**根因**：`wscript.exe` / `cscript` 是已知 LOLBin，安全策略直接拒。

**解法**：用 Python 的 `CREATE_NO_WINDOW`：
```python
import subprocess
subprocess.Popen(cmd, creationflags=0x08000000, close_fds=True)
```

---

## 附：JSON 解析容错（LLM 输出不稳定）

LLM 输出的 JSON 常有：```json 围栏、解释文字、嵌套超 1 层、中途截断、尾随逗号。

**五级容错链**：
1. 剥代码围栏 `re.sub(r"^```(?:json)?\s*|\s*```$", "", s)`
2. 去尾随逗号 `re.sub(r",\s*([}\]])", r"\1", s)`
3. **栈匹配**（支持任意深度嵌套）—— 原来用正则只支持 1 层，必失败
4. 截断修复（逐步回退 + 补引号 + 补括号，标 `_repaired`）
5. 原正则兜底

**实测**：7 用例通过 6（空/None 合理失败）。修复前因此浪费约 11 轮/天。
