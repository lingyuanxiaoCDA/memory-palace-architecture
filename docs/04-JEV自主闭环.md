# 04 · JEV 自主闭环设计

## 一、什么是 JEV 自主闭环

JEV 不是某个具体软件，而是**"自主性工程"的参考范式**（出自 AgentKthx 决策模式 + dsh-autonomy 自主性滑棒的融合思路）。

核心是**四环闭环**：

```
[感知] 巡检/心跳发现事件
   ↓
[决策] 事件 → 决策映射表匹配 → 授权内自主 / 超权请示     ← JEV 的核心
   ↓
[执行] 系统脚本 / AI / 工具群
   ↓
[学习] 结果回写 → 记忆沉淀 → 更新决策表
   ↓（循环）
```

## 二、自主性 5 档

```
L0 严格遵循：只执行明确指令（紧急/真金操作时）
L1 授权内自主：已知事件类型 → 预设动作（默认）
L2 主动探索：发现异常 → 自主诊断 → 自主修复
L3 自我进化：从任务提取技能 → 沉淀 → 优化决策
L4 天马行空：跨域联想（高价值但需护栏）
```

## 三、与记忆系统的结合

| 环 | 记忆系统的角色 |
|---|---|
| **感知** | 中枢 5 分钟巡检 + 心跳 → 事件 |
| **决策** | **先查决策表**（已知事件→预设动作），表外才问 LLM；检索记忆用规则路由（4.8ms）不用 LLM |
| **执行** | AI（凌麒）+ 系统脚本 + 工具群 |
| **学习** | 执行结果回写 → auto_mine 入库 → 更新决策表 + 路由器标注 |

## 四、关键认知：LLM 只在表外工作

没有决策表时，AI 每轮用 LLM"自由决定"做什么——慢、贵、易漂移（实测：6 小时审计没结论）。

加上决策表后：
```
已知事件 → 查表直接执行（毫秒级）
未知事件 → 才调 LLM 思考
```

**这正好解决"每轮重新想"的问题。**

## 五、最小落地（决策表）

```json
[
  {"event": "30m 解锁",     "action": "验证配置+首日观察+记录", "perm": "自主"},
  {"event": "5m CLOSED",    "action": "诊断原因+记录+观察",     "perm": "自主"},
  {"event": "双腿 acc 异常", "action": "查 verify+记录",        "perm": "自主"},
  {"event": "记忆异常",      "action": "心跳已处理+记录",        "perm": "自主"},
  {"event": "真金相关",      "action": "写 WAKE+推送请示",       "perm": "请示"}
]
```

**原则**：所有"自主"方向由**已验证结论**约束（决策表规则来自实测，非 LLM 猜）。
