# 05 · 凌麒改造实战：从"每轮失忆"到"联想激活"

## 一、改造前的凌麒（问题清单）

| 症状 | 实测证据 |
|---|---|
| 每轮只能看 1500 字日记尾部 | `mind.py`: `ctx['diary_tail'][-1500:]` |
| 98% 记忆搜不到 | recall 只查 SQLite（260 条），漏了 Chroma 45,552 条 |
| 一轮只能干一件事 | 一个动作用完一整轮 |
| JSON 解析失败浪费整轮 | 约 11 轮/天降级成 think |
| "记忆审计 6 小时没结论" | 每轮都在重新摸索 |

## 二、六项改造（当晚完成）

### 1. 会话结构（session.py）
```python
# 改造前：只看日记尾部 1500 字
# 改造后：完整对话历史
append_turn("assistant", body, action=...)   # 每轮写入
current_turns(limit=80, max_chars=200000)    # 下轮全量注入
rotate(task, conclusions)                    # 归档 + 提炼结论进 MEMORY
```

### 2. 记忆目录（memory_index）
不给全文，给**目录**（35 项资产：文件名/大小/时间/摘要）——它自己决定读什么。

### 3. 三通道检索
```
recall_chroma  → Chroma 45,552 + 同 wing/room 膨胀（联想）
recall_palace  → SQLite 260+235 + vitality 加权
recall         → 文本文件
```

### 4. 轮内动态插拔（decide_loop）
```python
COLLECT_ACTS = {"recall", "read", "search", "browse"}

def decide_loop(ctx, max_steps=6):
    d = decide(ctx)
    for step in range(max_steps):
        if d.get("action") not in COLLECT_ACTS:
            break                    # 实质动作 → 执行
        result = act(d)              # 收集信息
        ctx2["collected"] = trail[-4:]   # 插入上下文（只留最近 4 条，防爆）
        d = decide(ctx2)             # 再次调用 LLM
    return d
```
**效果**：一轮内可以"查→读→查→执行"，不用分 3 轮。

### 5. JSON 容错（详见 03 踩坑）
五级容错链，把 11 轮/天的浪费降到 1-2 轮。

### 6. 去硬截断
```python
# 改造前：MEMORY 只注入前 4000 字符、lessons 前 3500
# 改造后：全量注入（1M 上下文只用了 0.7%，没有理由截断）
```

## 三、改造效果

| 指标 | 改造前 | 改造后 |
|---|---|---|
| 每轮可见上下文 | diary 尾部 1500 字 | 记忆目录 + 完整会话 + MEMORY 全量 + 可主动检索 |
| 一轮能做几件事 | 1 件 | 最多 6 次推理 + N 次检索 + 1 次执行 |
| 可检索记忆 | 260 条（5.7%） | 45,552 条（100%） |
| JSON 失败浪费 | 11 轮/天 | 1-2 轮/天 |
| 会话记录 | 无 | 37+ 轮完整历史 |

## 四、一个有趣的验证

改造后它自己报告：
> "psutil 在 Python 3.13 下循环导入失败，改用 os + open + tasklist 绕过"

**它遇到了和主 agent 一样的坑，并且自己绕过去了**——说明修复后它能正常干活、正常记录。

## 五、可复用的要点

```
1. 记忆要"目录 + 自取"，不是"全文硬塞"
2. 检索要三通道（向量库 + 关系库 + 文本）
3. 收集类动作要能在一轮内连续做（结果即时插回上下文）
4. JSON 解析必须容错（围栏/嵌套/截断/尾逗号）
5. 上下文不要设小编码上限——先量后截（1M 只用 0.7%）
```
